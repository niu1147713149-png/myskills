# Design Nvwa - 智能设计路由系统

## 概述

Design Nvwa 是一个智能设计路由系统，能够：
1. 主动采集用户的设计需求
2. 根据需求特征智能分流到三条设计路线之一
3. 调用对应的设计工具输出完整的设计方案

## 三条设计路线

### 路线 1：纯创意设计
**触发条件：**
- 用户强调"风格独特"、"天马行空"、"创新"、"艺术化"
- 明确表示"不需要规范"、"自由发挥"
- 追求视觉冲击力和独特性

**处理方式：**
- 直接调用 `frontend-design` skill
- 以纯创意方式生成设计方案
- 注重视觉表现力和创新性

### 路线 2：纯参考设计
**触发条件：**
- 用户强调"规范性"、"参考成熟案例"、"稳妥"
- 明确表示"不要太创新"、"行业标准"、"最佳实践"
- 希望使用已验证的设计模式

**处理方式：**
- 调用 `ui-ux-pro-max` skill
- 从设计系统库中检索符合需求的案例
- 提供规范化、成熟的设计方案

### 路线 3：创意与规范结合
**触发条件：**
- 用户同时要求"风格独特"和"遵循规范"
- 表达"两者兼顾"、"在规范基础上创新"
- 既要专业性又要独特性

**处理方式：**
- 第一步：调用 `ui-ux-pro-max` 获取规范参考（设计系统、组件规范等）
- 第二步：基于规范参考，调用 `frontend-design` 进行创意设计
- 输出融合规范与创意的设计方案

## 实施流程

### 必须完成的任务清单

使用 TodoWrite 工具创建以下任务并依次完成：

1. **了解项目背景** - 检查现有项目文件、设计资产、技术栈
2. **询问基础需求** - 网站/应用类型、目标用户、核心功能
3. **询问设计偏好** - 风格倾向、颜色偏好、参考网站
4. **询问规范要求** - 是否需要遵循设计规范、是否参考案例
5. **判断设计路线** - 根据回答分析并明确告知用户选择的路线
6. **调用对应 skill** - 执行相应的设计 skill
7. **输出设计方案** - 呈现完整的设计方案给用户

### 详细实施步骤

#### 第 1 步：探索项目背景

```markdown
在开始询问之前，先了解：
- 检查项目目录结构
- 查看是否已有设计文件（CSS、设计文档等）
- 了解技术栈（React、Vue、纯 HTML 等）
- 查看 README 或项目文档
```

#### 第 2 步：需求采集（一次一个问题）

**问题序列：**

1. **项目类型**
   ```
   你要设计的是什么类型的项目？
   A. 企业官网
   B. 电商平台
   C. 管理后台
   D. 个人作品集
   E. 其他（请说明）
   ```

2. **风格偏好**
   ```
   你希望设计风格是怎样的？
   A. 现代简约（干净、留白多）
   B. 科技感（渐变、动效、未来感）
   C. 艺术创意（独特、视觉冲击）
   D. 传统商务（稳重、专业）
   E. 其他（请描述）
   ```

3. **规范性要求**（关键判断依据）
   ```
   关于设计规范，你的想法是？
   A. 需要严格遵循设计规范和最佳实践
   B. 完全不需要规范，追求独特创新
   C. 在规范基础上适当创新
   D. 不确定，听你的建议
   ```

4. **参考案例**
   ```
   你有没有喜欢的参考网站或案例？
   （请提供 URL 或描述风格）
   ```

5. **技术偏好**
   ```
   你希望使用什么技术实现？
   A. React + Tailwind
   B. Vue + Element UI
   C. 纯 HTML/CSS
   D. Next.js
   E. 其他（请说明）
   ```

#### 第 3 步：路线判断逻辑

根据用户回答进行关键词匹配：

**路线 1 触发关键词：**
- "独特"、"创新"、"天马行空"、"艺术"、"不需要规范"、"自由发挥"
- 问题 3 选择 B
- 强调视觉冲击和独特性

**路线 2 触发关键词：**
- "规范"、"标准"、"成熟案例"、"稳妥"、"不要太创新"、"最佳实践"
- 问题 3 选择 A
- 提供了具体的参考案例要求复刻

**路线 3 触发关键词：**
- "兼顾"、"在规范基础上创新"、"既要...又要..."
- 问题 3 选择 C
- 同时提到创新和规范

**判断后告知用户：**
```markdown
根据你的需求，我建议采用【路线 X】：[路线名称]

这条路线会：
- [说明该路线的特点]
- [说明将使用的工具]
- [说明预期的输出]

是否同意这个方案？
```

#### 第 4 步：执行设计

根据判断的路线执行相应操作：

**路线 1 实施：**
```markdown
1. 总结用户需求（风格、功能、技术栈）
2. 调用 frontend-design skill
3. 在调用时强调：创意优先、独特性、视觉冲击力
```

**路线 2 实施：**
```markdown
1. 整理规范要求和参考案例
2. 调用 ui-ux-pro-max skill
3. 在调用时强调：遵循规范、使用成熟模式、参考案例库
```

**路线 3 实施：**
```markdown
1. 第一阶段：调用 ui-ux-pro-max 获取规范参考
   - 请求设计系统建议
   - 获取组件规范
   - 了解最佳实践

2. 第二阶段：基于规范参考调用 frontend-design
   - 将规范要求作为约束条件
   - 在规范框架内进行创意设计
   - 确保既符合规范又有独特性

3. 输出融合方案
```

#### 第 5 步：方案输出

**输出内容应包括：**
1. 设计说明（设计理念、风格说明）
2. 完整的实现代码（HTML/CSS/JS）
3. 使用的技术栈和依赖
4. 实施步骤和注意事项
5. 后续优化建议

## 调用 Skills 的方法

在 Claude Code 中使用 Skill 工具来调用其他 skills：

```python
# 调用 frontend-design
Skill(skill="frontend-design")

# 调用 ui-ux-pro-max
Skill(skill="ui-ux-pro-max")
```

## 关键原则

1. **一次一个问题** - 不要一次问太多问题，循序渐进
2. **明确告知路线** - 判断后清晰说明选择的路线和理由
3. **征求确认** - 在执行设计前确认用户同意方案
4. **充分沟通** - 如果需求不清楚，继续追问直到明确
5. **灵活调整** - 如果用户不满意路线选择，可以重新判断

## 使用示例

### 示例 1：纯创意路线

```
用户："我想做一个个人作品集网站，要很酷炫，不需要遵循什么规范，天马行空的那种"

AI 判断：触发路线 1（纯创意）
- 关键词："酷炫"、"不需要规范"、"天马行空"

AI 响应：
"根据你的需求，我建议采用【路线 1：纯创意设计】。
这条路线会直接使用 frontend-design 工具，为你打造一个独特、视觉冲击力强的作品集网站，不受传统规范束缚。
是否同意？"

用户确认后 → 调用 frontend-design skill
```

### 示例 2：纯参考路线

```
用户："我需要一个企业管理后台，要符合行业标准，参考主流的后台管理系统就行，不要太创新"

AI 判断：触发路线 2（纯参考）
- 关键词："符合标准"、"参考主流"、"不要太创新"

AI 响应：
"根据你的需求，我建议采用【路线 2：纯参考设计】。
这条路线会使用 ui-ux-pro-max 工具，基于成熟的设计系统和最佳实践，为你提供一个规范、稳定的管理后台界面。
是否同意？"

用户确认后 → 调用 ui-ux-pro-max skill
```

### 示例 3：创意+规范路线

```
用户："我要做一个电商网站，既要符合电商行业的用户习惯和规范，又要有自己独特的品牌风格"

AI 判断：触发路线 3（创意+规范）
- 关键词："符合规范"、"独特的品牌风格"、"既要...又要..."

AI 响应：
"根据你的需求，我建议采用【路线 3：创意与规范结合】。
这条路线会分两步：
1. 先用 ui-ux-pro-max 获取电商设计的规范和最佳实践
2. 再用 frontend-design 在规范基础上打造独特的品牌风格
这样既能保证用户体验符合行业标准，又能凸显你的品牌特色。
是否同意？"

用户确认后 → 先调用 ui-ux-pro-max，再调用 frontend-design
```

## 错误处理

1. **如果用户需求模糊** - 继续追问，不要假设
2. **如果无法判断路线** - 列出各路线的特点，让用户直接选择
3. **如果 skill 调用失败** - 说明情况，提供替代方案或手动设计
4. **如果用户不满意输出** - 询问具体问题，必要时切换路线重新设计

## 完成标志

当以下条件全部满足时，design-nvwa skill 任务完成：
- ✅ 已充分了解用户需求
- ✅ 已明确判断并告知设计路线
- ✅ 已成功调用相应的设计 skill
- ✅ 已向用户呈现完整的设计方案
- ✅ 用户对方案表示满意或提出了明确的修改意见

## 注意事项

1. **不要跳过需求采集** - 即使看起来很简单的需求，也要完整询问
2. **不要假设用户意图** - 基于实际回答判断，不要主观臆断
3. **保持透明** - 让用户知道你在做什么、为什么这么做
4. **尊重用户选择** - 如果用户不同意你的判断，接受并调整
